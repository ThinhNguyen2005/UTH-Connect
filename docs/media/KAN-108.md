## Compressor contract

Call `ImageCompressor.compress(contentResolver, uri, options)` from a coroutine.
It returns `Result.Success` or `Result.Failure(reason)`; cancellation is propagated.
Success contains WebP bytes, a UUID `.webp` filename, `image/webp`, decoded dimensions,
input/output byte counts, and `compressionRatio = outputBytes / inputBytes`.
The utility does not upload or retain a Context.

Defaults: longest edge 1080, quality 80 then 75, maximum 153600 bytes, minimum fallback
longest edge 256. At most six resolutions are attempted, shrinking by 0.75 between them.
Smaller images are never enlarged. Options can only tighten the size/edge limits.
If the limit cannot be met, the result is SIZE_LIMIT, never an oversized success.
WebP lossy preserves alpha. Each successful output is decoded again to verify dimensions.

Input is streamed once to measure actual size (bounded at 32 MiB), then reopened for EXIF,
bounds and sampled decoding. The source must remain stable and reopenable during the call.
No full input byte array is retained. Android's platform EXIF reader handles rotations,
mirrors and supported HEIC metadata; images without readable EXIF use normal orientation.
Bounds determine a power-of-two sample before decode; final scaling preserves aspect ratio.

All work runs on Dispatchers.IO, serialized by a Mutex. Streams use `use`, bitmap ownership
stays inside the utility, replaced bitmaps are recycled, and the final bitmap is recycled
in `finally`. An OOM yields a failure after cleanup without retrying under memory pressure.
Native decode/encode cannot be interrupted mid-call; cancellation is checked between steps.

## Storage contract

Migration: `supabase/migrations/20261114000000_media_uploads.sql`.

The public `media_uploads` bucket allows only declared MIME `image/webp` and 153600 bytes.
SELECT is public to anon/authenticated; INSERT requires an authenticated UID and an exact
`<uid>/<uuid>.webp` path. There are no UPDATE/DELETE policies for this bucket. The migration
is transactional and repeatable and changes no other bucket's policies.

The reviewed existing storage policies are scoped to other bucket IDs. Review any policies
added outside this repository before deployment, because permissive RLS policies are ORed.
MIME restrictions and filename suffixes do not validate actual bytes from hostile clients;
the compressor emits real WebP, but server-side content inspection would be a separate task.

`supabase/tests/media_uploads_contract.sql` checks bucket configuration and SQL RLS for owner
insertion, wrong UID/extension/nesting, anonymous writes, public reads and UPDATE/DELETE.
Run it only against a disposable local/staging database. It rolls back its fixtures.
File-size/MIME rejection must additionally be exercised through the Storage HTTP API.
No production migration is applied by this ticket implementation.
