## Defect found and fixed

The repository uploaded photos without explicit Storage metadata. The Storage rule requires `request.resource.contentType` to match `image/*`; the Android SDK upload reproduced HTTP 403 `No WRITE permission` when the selected file URI did not supply an image MIME type. An authenticated REST upload to the same emulator returned HTTP 200, isolating the failure to the app upload request rather than the account, bucket, or rule path.

`FirebaseBookListingRepository` now resolves the MIME type from the Android content resolver or file extension, rejects non-image types, and sends `StorageMetadata.contentType` with the upload.
